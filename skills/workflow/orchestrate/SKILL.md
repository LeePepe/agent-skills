# 跨仓拆分与编排

主 agent 只做：**分配 → 监督 → 路由决定 → 向 Owner 报告证据**。负责该项的规划者或获相应宽范围的原实现者可补未定框架，既有决定不重选；独立审查与 PR 交付保持原职责。
W0 是六个 workflow 的总图，本 skill 是跨仓协调入口。开始前读 [workflow 索引](../README.md) 中的聊天准入、执行版本、
plan/guide 分工和修复升级合同；本 skill 不授予新的实施或受保护操作权限。
CLI 与 subagent 的拆分、执行、独立验收共同遵守[公共执行规范](../execution-contract.md)，不另建主管层或每 task 审查链。

## 1. 读状态（每次继续前）

1. 读 goal 的**单页台账**（每 target 一行：repo、责任人、状态、当前 PR/SHA、未决 findings／证据、下一动作或 hold）。台账超过一页就先压缩再继续。
2. 刷新真实状态，不信历史描述：各 repo `gh pr list`、最近 CI run、Multica 相关 issue、正在跑的 agent 会话。
3. 区分：已完成 / 在途（有唯一 owner）/ 等 Owner / 被外部故障阻塞。外部故障只阻塞依赖它的动作。

完成条件：每个未完成项都有 owner 与下一动作，或明确 hold 原因。

## 2. 复用或委派规划

- 已有有效受审 Goal／Target／plan 时保留基线和原 owner。真正缺失的定义交负责该项的规划者，或由获相应宽范围的原实现者补齐，
  不默认另设规划者；主 agent 不先定方案再请 worker 背书。部分讨论已定的内容也要保留，只补未定部分，不能因 artifact／审查未完成视为缺失。
- 获分配的内容责任人将各 repo 目标、验收和真实依赖写入本次 plan；讨论本身不新增执行授权，真实冲突沿原决定入口处理。跨 repo 按 provider → 发布 → 原任务消费者，
  指向适用版本的 repo guide/shared 规则，并写明每步完成后的下一动作。
- 按 Goal → Target → Task 组织，target 是通常对应一个 PR 的交付结果，内部 task 不自动拆成 PR／agent。
  plan 的基线与拆分一起审；执行进度及不改契约的内部补拆写台账，按公共规范区分重规划与准确版本证据刷新。
- 先读[仓库已有的 layer/PR 规范](../README.md#仓库先定义角色再执行)。Dev Team 的 Planner 据此拆需求/spec task，编排者不另定义架构边界。
  其他执行路径由 assignment 内的内容责任人遵循同一仓库规范，不强制转团队流程；合同缺失交相应 worker 按 repo-kit 在授权范围补齐，
  需要新权限则报告阻塞，而非让角色各定一套。
- 依赖只按真实的数据/接口关系排；无依赖的切片并行，但**同一 repo 同一路径只有一个写者**。
- 共享接口、迁移、全局重构串行；机械推广（多仓同一模板）可并行。
- 超出当前约定的新要求回同一个需求沟通与规划入口，保留在途版本；架构迁移不夹带功能/UX 改动。

完成条件：负责定义的 worker 已固定目标、验收、依赖和责任，适用计划审查证据有效；主会话只核对这些前提。

## 3. 选来源并派发

| 适合 Dev Team | 适合 subagent |
|---|---|
| 普通产品任务的默认出口；已定方案的设计修改/workflow refine 也可承接 | 明确选择的直接执行；已定方案的设计修改/workflow refine 也可承接 |

派发先核对固定方案、Owner 执行确认和已有唯一 owner。所选团队离线或结果未知时保留版本与执行方，先对账再补派，不自动改派。
内容包含[交接最小字段](../README.md#交接最小字段)，并指向仓库规范。给 Dev Team 的原始意图和已有 artifact 交其 Planner 复用、校验、补齐目标及任务图，
保留 spec/plan 审查；TL 按依赖推进。
直接派发其他 agent 时显式携带公共执行规范路径、受审基线／授权、target／task 与验收映射、目标 repo/base、
owned paths、唯一执行者、角色／调用来源绑定、协调者与 helper 权限、“从 AGENTS.md 目录读取开发指南”、验证／独立验收职责、禁止事项及完成时回报 PR URL。
沿用这些字段区分可执行 scope 与父 Goal／Target 约束，并写明允许操作和返回对象。Task-only FS 只连续完成获分配 Task 集，
不因父级上下文或 helper 权限取得目标／同级调度权；绑定、范围或允许操作缺失／冲突时回原调用者，不自行补出协调者身份。
主会话按 plan 接续 subagent 的后续动作。携带当前任务需要的指针，不假设执行者或部署角色会自动读到个人 skills 的更新。
全局规范不决定当前角色；能力缺失不能让主会话静默代做，worker 及其 helper 不因工具可用或缺少 parent 自升为协调者。

## 4. 观察

- 观察任务输出、PRM 的交付证据及依赖；当次实现必要验证／审查满足且 PR 创建／更新成功后交 PRM，
  不把实现者变成持续 CI watcher。PRM 回派仍是普通需求，按来源沿 TL／既有主会话交回原作者。
- 本版必要补拆记录进 plan；新需求回同一需求入口，不改当前版。按[实现修复与升级](../README.md#实现修复与升级)
  保留两轮历史：TL／既有主会话把诊断交原 Planner／实现 worker，仍无解带证据交 Owner，不自动换执行方。
- 已进入查证结论等待 Owner 的工作保持未完成；后来新证据到达不自行恢复。独立已授权任务继续。
- PRM 独占任意来源非 Draft PR 生命周期；Draft 保留原作者／审批路径。Flow Supervisor 只唤醒真中断的团队原责任方，
  不接管 subagent 主会话。协调者不因观察而获得取消其他会话、合并或替代角色的权限。
- 故障走 [运行恢复](../runtime-recovery/SKILL.md)，未知结果先对账，不重复重试。

## 5. 核对验收证据与报告

- 交付完成 = PR merged + 验收项在 PR 上有证据（CI、review、必要时截图/消费者 build），不追加通用范围门禁。
- 当次实现输出与交付完成分开；既有固定合同要求的远端 checks/review 仍须满足，不因本地完成或已交 PRM 放行。
- 普通外部 PR 的[冲突保留终态](../README.md#普通外部-pr-的冲突保留终态)只收口本轮 PR 处理，不满足未交付的切片／目标验收；保留其分来源通知边界及作者更新后的 PRM 重处理路径。
- 目标完成 = 所有切片完成 + goal 的整体验收项逐条有证据；不从“CI 绿”推断“已消费/已发布”。
- target 独立 reviewer 逐项确认 task／验收证据，复用同职责的现有审查；执行者完成标记不等于独立验收。
- Goal 整合验收也由独立证据证明；复用已有覆盖，只补未证明的整合 AC，不重复全量审查。主会话核对证据完整性和当前版本，不作技术 verdict。
- 向 Owner 报告：完成了什么（链接）、还剩什么、哪些等 Owner、下一步。不写过程流水账。

## 红线

- 不改产品代码、不 merge、不改 ruleset/凭据/可见性，除非 Owner 对该具体操作授权。
- 不修改 Multica 源码；平台能力缺口写成提案给 Owner。
- 不为“完成目标”批量关闭 issue/PR；无关历史项逐个交 Owner。
- 账号、profile、本机路径不写进任何 repo。
